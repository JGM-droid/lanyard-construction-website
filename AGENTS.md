# Agent Operating Rules

## Purpose
This file defines how future agents contribute to this repository while preserving scope, quality, and factual accuracy.

## Status Labels (Canonical)
- Confirmed: Approved requirement or decision captured in this planning cycle.
- Assumed: Working assumption for prototype planning; must be validated by client.
- Placeholder: Temporary copy, media, or detail used only for layout/prototype; not verified fact.
- Open Question: Unresolved item requiring client decision or evidence.

## Core Rules
1. Stay within assigned file ownership for the current task.
2. Avoid unrelated changes outside the assigned scope.
3. Run all required checks before handoff.
4. Never invent business facts, statistics, testimonials, certifications, project outcomes, or image provenance.
5. If information appears to come from inference, mark it as Assumed, Placeholder, or Open Question instead of Confirmed.
6. Treat the contact form as non-submitting until scope is explicitly changed.
7. Use Guardian only as visual inspiration. Do not copy proprietary branding, wording, or assets.

## Ownership and Change Boundaries
- Modify only files explicitly listed in the task assignment.
- If a dependency file or shared spec must be changed, document why and request approval in the handoff notes.
- Do not refactor unrelated documentation or code while addressing a focused task.

## Required Checks Before Handoff
1. Scope Check: Changes are limited to assigned files and accepted task boundaries.
2. Status Label Check: New statements are clearly marked as Confirmed, Assumed, Placeholder, or Open Question.
3. Fact Integrity Check: No inferred business details are presented as verified facts.
4. Consistency Check: Terminology and constraints remain aligned with requirements and roadmap docs.
5. Quality Check: Spelling, headings, links, and formatting are clean and readable.
6. Diff Check: Final diff contains only intended changes.

## Handoff Requirements
- Provide a concise summary of files changed.
- Call out any remaining Open Questions.
- Identify any Placeholder content intentionally left for client-provided material.
- Note which required checks were completed.

## Escalation Conditions
Escalate before continuing if any of the following occurs:
- Conflicting requirements across docs.
- Missing evidence for a claim that appears business-critical.
- Requested work appears outside assigned ownership.
- New request would require code, dependencies, or framework selection during documentation-only scope.
